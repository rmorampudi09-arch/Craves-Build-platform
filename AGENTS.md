# Rules for agents and people working in this repo

**Never break or remove anything production is running.** Read `docs/runbooks/live-runtime-safety.md` before building, deploying or changing a service.

- Production is Azure subscription 34eefd95 (tenant 182d6285) since 29 Oct 2026, released by Azure DevOps org ravitejamm6, project Craves-New-Original: a mirror copies GitHub `main` into Azure Repos every 15 minutes, and a change under a service's folder releases that service by itself (canary, automatic rollback). Merging to `main` deploys to production. Names and ids are in docs/runbooks/production-environment.md. Subscription 721906c9 and the rmorampudi09 DevOps org are the idle fallback from before the move: never deploy there. Subscription 4f897b61, names ending l3ing6, registry cravesprodlowacr82121, Craves-Dev-Service-Connection and the ravitejamorampudi7777 org are retired: never use them.
- Never release through the old Azure DevOps org rmorampudi09/Craves: since 29 Oct 2026 its pipelines deploy into the old subscription, not production. Pipelines 3, 4, 6, 7, 8, 9, 10, 11, 14, 20 and 21 there were also turned off on purpose on 27 Oct 2026 because they run old Azure Repos copies: never run, re-enable, copy or recreate them, and never ask the owner to, even when an older doc, note or chat says so. If a task seems to need a release, merge to GitHub `main`; if that doesn't fit, stop and ask.
- Deploy only code that is on GitHub `main`. If you build from a branch, Azure Repos or your machine, merge that source to `main` the same day, and put the commit in the image tag.
- Before rebuilding a service from `main`, check that `main` contains everything the live image runs (see the runbook).
- Each backend service has `src/main/resources/live-runtime-lock.txt`. In production, a build that lacks any listed class refuses to start. Never delete a line to get a deploy through: restore the missing code. Remove a line only when retiring that code on purpose, and say so in the PR.
- When you add a controller, add it to that service's lock file. CI (`scripts/release/tests/test_launch_live_runtime_lock.py`) enforces this.
- Flyway migrations are append-only. Never renumber or edit one that production has applied.
